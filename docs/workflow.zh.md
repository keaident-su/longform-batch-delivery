# 完整工作流（中文）

本文是 [SKILL.md](../SKILL.md) 的操作手册。

---

## 第 0 步：判断是否需要分批

```
需要分批  ⟺  目标字数 > 单轮安全产出（8,000 ~ 10,000 中文字符）
```

一旦需要分批，**立刻**停止"边写边想"，改走下面的流程。

---

## 第 1 步：测算并告知轮数

计算公式：

```
P = 单轮安全产出      （保守取 8,000；宽松取 10,000）
N = ceil(目标字数 / P)
```

然后**在第一次回复里**给出：

- 目标字数
- 单批预算 P
- 计划批数 N
- 每批覆盖的范围
- 一句明确的话：「这需要 N 轮，不是一轮」

> 关键：把"轮数"这件事在第一时间讲清楚。用户在后面就不会有"怎么还没写完"的落差感。

---

## 第 2 步：建立账本

```bash
python scripts/ledger.py init --target 170000 --budget 10000
```

生成 `ledger.json`（机器读）+ `LEDGER.md`（人读）。

账本里两个最重要的字段：

- `current_total`：当前累计字数
- `cursor`：续写游标（下一批从哪开始）

---

## 第 3 步：骨架先行

**先写目录，后写正文。**

骨架里每个单元只占三样东西：

```
第171场
锚点：<一句话>
计划字数：900
```

骨架一次交付给用户确认。这一步很便宜，能省掉后面所有返工。

**锁定两样东西**：单元编号、时间顺序。之后每一批都只能在这两者之内填字。

---

## 第 4 步：单批作业循环

```
┌─ 读 LEDGER.md，确认本批范围
│
├─ 写正文（目标 = per_batch_budget，宁少勿超）
│     └─ 落盘为源文件：src/part_01.txt, src/part_02.txt ...
│
├─ 跑体检：python scripts/build_and_verify.py --src "src/*.txt" ...
│
├─ 登记：python scripts/ledger.py add --n K --range "..." --added <本批字数> --verify PASS
│
├─ 汇报（固定格式，见下）
│
└─ 停。等用户说「继续」。
```

**汇报固定格式：**

```
## 第 K 批已交付
| | 上轮 | 本轮 | 增量 |
|---|---|---|---|
| 合计 | … | … | … |

目标 X ｜ 当前 Y ｜ 还差 Z（完成度 P%）
新增：<这批写了什么>
校验：G1✓ G2✓ G3✓ G4✓ G5✓ G6✓ G7✓
下一批：<范围 + 计划字数>
```

---

## 第 5 步：断点续写

用户说「继续」时：

1. `python scripts/ledger.py next` → 得到下一批范围与计划字数；
2. 直接写，**不要重新问需求**；
3. 写完回到第 4 步。

因为账本在磁盘上，所以**换会话、被压缩、隔了几天**都能无缝接上。

---

## 校验闸门一览

| 闸门 | 检查什么 | 失败怎么办 |
|---|---|---|
| G1 | 字数单调增长，达标 | 立刻补写，不拖到下一批 |
| G2 | 单元编号连续、附属单元紧跟 | 重排 + 全局回写 |
| G3 | 时间戳严格递增 | 调整时间戳 |
| G4 | 必填字段齐全 | 补齐 |
| G5 | 卷/集/章标题齐全 | 补标 |
| G6 | 退化（碎片断句 / 空行注水 / 高重复） | 改写 |
| G7 | 交付文件可打开 | 重生成 |

`build_and_verify.py` 覆盖 G2—G6；G1 看账本；G7 交给目标软件验证。

---

## 常见坑

1. **同一批里回头改历史章节** → 校验基线失效。要改就单独开一批，并全量重跑。
2. **把正文贴在聊天里** → 既占上下文又容易丢。永远落盘。
3. **用"补充场/附录"堆字数** → 主线不推进等于注水。补写要写"同一事件的其他视角/因果/内心"。
4. **进度只存在对话里** → 换会话归零。必须落盘。
5. **最后才汇报字数缺口** → 最伤用户。每批都报，缺口永远可见。
