# 工作流（中文）

## 0. 开局三件事

1. **测算**：`N0 = ceil(目标 ÷ 9000)`，把 N0 告诉用户。
2. **写死分批计划**：出一张"批次 / 范围 / 计划字数 / 累计"的表。
3. **建账本**：`python scripts/ledger.py init --target 170000 --parts "上册:238" "下册:0"`

## 0.5 停止谓词与轮末契约（v8 必读，优先级高于本文其余部分）

### 停止谓词：唯一合法的"完成"判据

```bash
python scripts/run_state.py gate
```

| 退出码 | 状态 | 该做什么 |
|---|---|---|
| **0** | `DONE` | 字数达标 + 闸门全过 + 交付物在 → **可以停**，可以写"完成" |
| **1** | `RUNNING` | 字数没到 → **接着写**，禁止写"完成"、禁止提问 |
| **2** | `BLOCKED` | 有必修复项 → **修完接着跑**，不是停下来问 |

### 轮末契约：每轮结尾二选一

- `✅ DONE`（仅当 `gate` 退出码为 0）
- `⏩ RESUME` + `run_state.py resume` 打印的原文（其余一切情况）

禁止出现：`要不要…`／`需要我继续吗？`／`如果你想…回我一句'继续'`。

### 一轮的标准动作

```bash
python scripts/run_state.py where    # 换会话先看清当前口径
python scripts/run_state.py plan     # 作业单：N 个单元 × 每单元至少 M 字
#   ……写正文，落盘（正文不进聊天）……
python scripts/run_state.py tick --added 9200 --units 5 --cursor 214   # 自动执行吞吐升级梯
python scripts/run_state.py gate     # 看退出码决定结尾
python scripts/run_state.py resume   # 需要续跑时输出那一行
```

## 1. 骨架先行

先只写骨架：每个场/章一行，`编号 + 一句锚点 + 计划字数`，不写正文。骨架先交付确认，之后只做"填肉"。
**填充时不许改编号与顺序。**

## 2. 单写者锁

项目根写 `RUN.lock`：

```json
{ "run_id": "2026-09-14T18:20", "file_prefixes": ["act4_"], "owner": "session-A" }
```

构建脚本只扫描 `file_prefixes`，其余同目录文件视为污染（G8 直接失败）。

## 3. 每批 SOP

```
1. 读 LEDGER.md → 取 cursor 与下一批范围
2. 只写这一批（目标 = 上一次实测的"字/轮"）
3. 落盘（文件名带序号）
4. python scripts/build_and_verify.py --target 170000
5. 字数不够 → 本批内补写，不许把差额留到下一批
6. python scripts/ledger.py update --added <本批新增> --blocks <本批块数> --cursor <最新编号>
7. 汇报（固定表）
8. python scripts/run_state.py gate
9. 退出码 0 → 结尾写 ✅ DONE；否则 → 回到第 1 步继续，结尾写 ⏩ RESUME
```

## 4. 汇报模板

```
## 第 N 批已交付
| | 上轮 | 本轮 | 增量 |
|---|---|---|---|
| 上册 | … | … | … |
| 下册 | … | … | … |
| 合计 | … | … | … |

目标 X ｜ 当前 Y ｜ 还差 Z（完成度 P%）
实测吞吐：字/块 = a ｜ 字/轮 = b ｜ 预计还需 r 轮

新增：<这批写了什么>
校验：G1✓ … G10✓
结尾：✅ DONE（仅 gate exit 0）或 ⏩ RESUME（其余一切情况）
下一批：<范围 + 计划字数>
```

## 5. 遇到"块很多但字数上不去"

看 G9 的未达标清单。**加长单块，不要增加块数。** 一个 300 字的补充场和一个 800 字的补充场，成本差不多，但后者才是有效产出。

## 5.5 跨来源拼接（v7 新增，必做）

只要底稿不是你从头写的（别人写的、更早批次写的、并行运行写的），**动笔前**先做三步：

```bash
python scripts/dedupe_scan.py scenes --cross-table --out g10.txt
```

1. 读 `g10.txt` 的“必须修复”区；先清 ERROR，再看 WARN。
2. 看你新写的每一个补充场在**逐场对照表**里的位置：时间在主场次之后，就绝不能再写主场次已经写完的动作。
3. 同一事件的细节（几个人、什么工具、什么缘由）**一律沿用底稿已确立的那版**，不得另起一套。

> 记住：G1–G9 保“长得对”，G10 保“说得不矛盾”。两者都过，才算交付。

### G10 输出怎么读

| 级别 | 含义 | 动作 |
|---|---|---|
| G10a 逐字重复 | 两块≥ 30 字完全相同 | 必改：改写或删除其中一块 |
| G10b 同场事实冲突 | 同场各块的互斥要素/数量打架 | 必改：按底稿统一，重建 |
| G10c 疑似重写 | 时间在后的补充场与主场次共享≥ 3 个收束动作 | 必改：换角度重写 |
| G10d 日期错位 | 正文日期比时间字段早30天以上 | 确认：引述/回顾可保留，否则改 |

## 6. 遇到"出现重号"

G8 会先失败。此时**不要自动合并**，人工决定留哪一份，删掉另一份，再跑一次构建。

## 7. 换会话续写

先跑 `python scripts/run_state.py where` 与 `plan`，读 `run_state.json` / `LEDGER.md`，取游标，用实测吞吐算范围，直接写。**不重问需求。**
