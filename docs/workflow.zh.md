## 一、开工：三件事

1. **写 `RUN.lock`**（单写者锁）

```json
{ "run_id": "2026-09-14T18:20", "file_prefixes": ["act4_"], "owner": "session-A" }
```

构建脚本只扫描 `file_prefixes` 里的文件；其余同前缀文件视为污染。
多个会话/并行运行时，同一目录**只能有一个 owner**。

2. **初始化账本**

```bash
python scripts/ledger.py init --target 170000 --prefix act4_
```

3. **算轮数**：`预估轮数 = ceil(目标 ÷ 9000)`，把这个数字**直接告诉用户**。

---

## 二、骨架先行

先只写"编号 + 一句锚点 + 计划字数"，不写正文；交付确认后，再一批一批填正文。
**填充时不得改动编号与顺序。**

---

## 三、单批 SOP

```
1. 读 LEDGER.md → 取 cursor 与下一批范围
2. 只写这一批（目标 = 实测字/轮）
3. 落盘（文件名带序号，遵循 RUN.lock 前缀）
4. python scripts/build_and_verify.py --dir scenes --mode scene --target 170000
5. 字数不够 → 本批内立刻补写
6. python scripts/ledger.py update --add <本批字数> --blocks <本批块数>
7. 按 §8 格式汇报
8. 连续模式 → 回到 1
```

---

## 四、连续模式（v7 的默认）

触发词：**"全部写完""不许停""连续处理""一直跑到达标"**。

触发之后：

- 同一轮回复内**连续跑批**：落盘 → 校验 → 更新账本 → 再落盘 → 再校验……
- **不许**中途停下问"要继续吗"。
- 只在两种情况下停：
  1. `done = true`（字数达标 且 G1–G10 全过）；
  2. 本轮的输出上限到了。
- 因 2 停下时，末尾必须给出：进度表 + "下一轮第一件事"。

---

## 五、报错了怎么办（排障）

| 症状 | 原因 | 动作 |
|---|---|---|
| 只写一批就停 | 没进入连续模式 | 回 SKILL.md §1 第 4 条 |
| 块数多、字数上不去 | 单块太短 | 看 `WORKLIST.md`，**加长单块** |
| 时间戳倒流 | 新补单元时间早于同场景既有最后补单元 | 先跑 `slot_allocator.py` 取安全窗口 |
| 出现两套同编号 | 多写者 | G8 失败即停，人工裁决，**绝不自动合并** |
| 换会话归零 | 进度只在对话里 | 账本必须落盘 |

---

## 六、收工条件

```bash
python scripts/size_report.py --dir scenes --target 170000
```

输出必须是：

```
目标 170000 ｜ 当前 170xxx ｜ 还差 0（100.0%）｜ done=True
```

并且 `build_and_verify.py` 的 G1–G10 全为 OK。**只有这时才可以宣布完成。**
