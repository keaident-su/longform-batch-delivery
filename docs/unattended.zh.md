# 无人值守跑长文（睡觉时也能跑完）

## 结论先说

Chatbox **没有**"自动进入下一回合"的按钮。回合只在"发出不含工具调用的消息"时结束，
而结束＝停下来等你输入。所以无人工续跑只有两条路：

1. **回合内不停**（LFBD v11 的 M0）：模型绝不发非工具消息，一个回合尽力多写。
2. **把消息队列当自动继续**：Chatbox 支持排队消息，**当前回复结束后队列里的下一条会自动发出**。

## 睡前三步（最省事）

1. 确认：工作模式 + 完全访问（Full Access）+ 会话设置里"每 25 步暂停"= **关**。
2. 打开 `templates/queue_resume.txt`，把里面 **20 行**逐条粘进输入框并回车（每条都入队）。
   队列上限 20 条，超了就排不进。
3. 去睡。客户端会自动一条接一条地把它们发出去。

## 一夜能跑多少

```
一夜产出 ≈ 队列条数 N × 每回合块数 k × 每块字数 c
```

| N | k | c | 一夜约 |
|---|---|---|---|
| 20 | 6 | 1,800 | 216,000 字 |

> 20 万字的第五幕，用这组参数一晚够。

## 绕不开的硬边界

* **单次响应输出上限**：一次回答能产的字数有天花板。
* **上下文窗口**：会话越长越挤；开着的 `autoCompaction` 会帮你压缩，但压不到零。
* **总输出量 x**：内容量本身不可压缩。

撞上这些边界时，模型会写一行 `⏩ RESUME` 后停下——那就再排一轮队列接着跑，不用重述需求。

## 真正的零人工（可选）

如果你有可调用的 LLM API Key，用 `scripts/overnight_driver.py` 在聊天**之外**跑循环：
读骨架 → 逐块生成 → 落盘 → `run_state.py gate` → 没到 0 就继续。它不受 Chatbox 回合与队列限制。
用法见该脚本顶部的 `--help`。
