# 长文本分批交付协议 LFBD v7

> 给 AI 智能体用的一份"把十几万字写完"的工程协议。
> **v7 只修一件事：让它真的连着写，写到达标为止，中途不许停下来问"要继续吗"。**

[English](README.md) ｜ [工作流文档](docs/workflow.zh.md)

---

## 它解决什么问题

让大模型一次性写完 10 万字，物理上不可能：单轮输出上限约 6,000–12,000 中文字符。
所以唯一的办法是"分批"。但市面上的做法普遍翻车在四个地方——v7 一条一条掐住：

| 编号 | 真实约束 | 常见翻车 | v7 的修法 |
|---|---|---|---|
| R1 | 单轮输出有硬上限，改提示词没用 | **写一批就停下来问"要继续吗"** | 把"一轮内连续跑批到上限"写成**默认动作**；把"只写一批就停"列为头号反模式 |
| R2 | 真实吞吐必须实测（常见只有 300–600 字/块） | 用"每轮一万字"估值排期，越写越远 | 第 1 批结束立刻标定 `字/块`、`字/轮`，用实测值重排 |
| R3 | 用短"补充单元"堆量会做成空心稿 | 块数很多、字数很少、主线不动 | **单元地板** + 未达标清单 + 命令你"加长单块，不许加块数" |
| R4 | 多轮/并行会把同一编号写两遍 | 两套稿子互相污染 | **单写者锁** + 构建前**重号即失败** |
| R5 | "完成"是模糊词，模型爱说"已完成" | 用户以为写完了，一查差一半 | **完成 = 可判定的式子**（见下） |

---

## v7 的核心：把"完成"变成一个式子

```
done = (当前字数 ≥ 目标字数) AND (G1–G10 全部通过)
```

- `done = false` 时，**任何"已完成""交付完毕"的措辞都是违规**。
- `done` 会写进 `ledger.json`，换会话也不丢。
- 断点续写时，第一件事就是读这个字段：`done=false` 就接着写，`done=true` 才收工。

## 四条你一定会用到的命令

```bash
# 1) 初始化账本
python scripts/ledger.py init --target 170000 --prefix act4_

# 2) 每批结束：重建 + 跑 G1–G10 + 生成下一批作业单
python scripts/build_and_verify.py --dir scenes --mode scene --target 170000

# 3) 随时问：还差多少、还要几轮、完了没
python scripts/size_report.py --dir scenes --target 170000

# 4) 补写前：给新单元找一个不会倒流的时间戳
python scripts/slot_allocator.py --file scenes/act4_e04_p1.txt --main 211
```

## 十道闸门

| 闸门 | 判据 |
|---|---|
| G1 字数 | 单调增长且 ≥ 本批承诺 |
| G2 编号 | 主编号无跳号、无重号 |
| G3 时间 | 时间戳严格递增，零倒流 |
| G4 字段 | 每单元必填字段齐全 |
| G5 结构 | 集/卷/章标题齐全 |
| G6 退化 | 无"主语，动词"碎片、无连续空行 ≥3 |
| G7 交付 | 产物能正常打开 |
| G8 重号污染 | 同编号不得出现在两个文件；**失败即停，人工裁决** |
| G9 单元地板 | 每单元字数 ≥ 地板 |
| **G10 达标** | `done` 成立与否 |

## 快速上手

1. 把本目录放进你的智能体 skills 目录（或直接读 `SKILL.md`）。
2. 在项目根写 `RUN.lock`，声明本次运行允许扫描的文件前缀。
3. 按 `docs/workflow.zh.md` 的 SOP 跑：骨架先行 → 连续跑批 → 每批校验 → 更新账本。
4. 触发连续模式的说法：**"全部写完""不许停""连续处理""一直跑到达标"**。
   智能体听到这些词后，一轮内必须连续提交多批直到输出上限。
